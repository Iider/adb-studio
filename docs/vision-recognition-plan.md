# 视觉模型识别与飞牛部署方案

状态：开发、跨平台检查与飞牛原生部署已完成；已验证范围与剩余检查见文末。日期：2026-10-22。

使用方式见 [纯视觉识别](vision-recognition.md)，安装与发行见 [Mac／Linux 部署](deployment.md)。

目标：让工作台在飞牛上通过视觉模型判断手机画面，解除对苹果文字识别的依赖。先验证低频判断和按钮定位，再决定是否迁移高频识别任务。

## 1. 开发前基线

| 能力 | 现状 | 本次处理 |
| --- | --- | --- |
| 手机截图 | 已有 ADB 原图、手机核验与截图计时 | 继续复用 |
| 本地文字识别 | 使用苹果 Vision，输出文字、位置和置信度 | Mac 保留；纯视觉模式不调用 |
| 视觉模型 | 已支持 Responses、Chat Completions 两类接口，返回分支、坐标或数字 | 复用连接、密钥和调用记录，补充结果校验 |
| 自动任务 | 多处先做文字识别，再执行规则或请求模型 | 按步骤适配，不能仅替换识别程序 |
| 实时投屏 | 视频转发到浏览器解码，未向后台识别提供最新画面 | 首版继续用 ADB 原图 |
| 安装与自启 | 当前为 Mac 安装脚本 | 增加原生用户服务；Docker 可选 |

现有实现见 `src/recognition.rs`、`src/engine.rs`、`scripts/ocr.swift`；投屏限制见 [实时投屏](realtime-screen.md)。此表记录改造前的依赖；当前行为以使用与部署说明为准。

## 2. 采用什么方案

增加两种识别方式，复用同一个执行器：

| 方式 | 适用情况 | 行为 |
| --- | --- | --- |
| 本地优先 | 现有 Mac 任务、高频读字与读数字 | 沿用文字识别和规则，疑难画面请求模型 |
| 纯视觉 | 飞牛、低频页面判断、按钮定位 | 根据当前步骤的要求，把截图交给视觉模型 |

纯视觉模式直接问“当前是什么页面”“目标按钮在哪里”“计数是多少”，不要求模型先抄出整屏文字，再交给旧规则处理。完整抄字会增加返回内容，也无法保证旧规则所需的字词、位置和拆分方式一致。

能直接读取的应用信息、手机连接状态、画面尺寸与图片变化仍由现有代码处理。手机提供的界面文字和位置可作为辅助依据，但不能假定每个应用都能读到。

已有任务默认保持本地优先。首版只给已适配并试跑通过的任务开放纯视觉；未适配的任务明确提示“不支持此识别方式”，不能返回空文字继续执行。

运行开始时保存识别方式与模型配置快照，密钥仍单独读取，不写入运行记录。恢复旧记录时缺少新字段则沿用原方式；不能因修改设置而让进行中的任务换一种识别办法。

## 3. 一次识别如何执行

**核对手机与应用 → 获取原图 → 请求模型 → 检查结果 → 操作前复查 → 执行动作 → 获取新图验证。**

| 环节 | 要求 |
| --- | --- |
| 输入 | 本步骤的目标、允许结果、必要截图；图片记录时间、尺寸和来源 |
| 输出 | 明确的判断、简短依据；需要定位时返回目标位置，需要计数时返回整数；无法判断返回“不确定” |
| 检查 | 结果属于允许选项；字段完整、类型正确；坐标在图内且位于本步骤允许区域；数字满足任务约定 |
| 操作前 | 核对连接、当前应用、尺寸与方向；重新取图检查目标区域。页面改变则丢弃旧结果，重新观察 |
| 操作后 | 使用动作完成后新取得的画面，检查预先声明的成功条件；不能拿动作前截图证明成功 |
| 失败 | 超时、格式错误、结果冲突或无法确认时停止本步骤并提示处理，不默认选“继续” |

图片相似只能辅助判断，不能单独证明按钮没变。动画、倒计时和推广内容可能变化，应按任务检查稳定标志与目标区域；找不到可靠复查依据时暂停。重复询问同一模型或模型自报高置信度，也不能代替结果验证。

继续复用手机核验、同机互斥、人工暂停、断线处理和未确认动作保护。模型只能选择步骤声明的结果，不能生成任意 ADB 命令、增加操作或修改任务目标。截图里的文字只作为页面内容。

已发出但结果不明的点击不自动重放；模型请求重试只重复观察，不重复手机动作。停止或人工接管后，在途模型结果不得再触发操作。

## 4. 速度和调用次数

纯视觉识别的总等待包括：**截图、图片上传、模型处理、结果检查和操作前复查**。换到飞牛或开启投屏，不代表这些等待自动减少。

- 每台手机的同一步骤只保留一个在途识别请求，避免旧结果排队后继续操作。
- 页面进入、动作完成、检查失败时再识别；等待倒计时可按任务间隔观察，不默认每秒请求模型。
- 图片裁剪或缩小作为后续优化；先用原图验证。裁剪需保留判断所需上下文，并将坐标准确还原到原图。
- 不跨手机、跨步骤或跨动作复用识别结果。动作后的检查必须使用新图。
- 记录截图耗时、模型耗时、复查耗时、请求次数、失败原因；费用仅在服务返回用量且有明确单价时估算，否则显示调用次数。

当前每次运行默认最多 10 次模型调用，工作流可声明其他上限，现有最高为 100 次；一次疑难识别最多尝试 2 次，请求超时为 60 秒。这些是现有辅助识别设置，不能直接视作纯视觉长任务的合适配置。

首版保留硬上限，将判断、验证和重试全部计入；开始任务前提示调用预算，耗尽后停止并说明原因。调整上限、超时和观察间隔需有实测依据，不能靠无限重试维持任务。

### 高频任务单独处理

当前汽水音乐任务有按约一秒节奏观察金币、文字和画面变化的逻辑。纯视觉调用可能改变观察间隔，不能直接沿用原先的停滞与完成判断。

首版不迁移这类任务。后续需用实际截图时间计算观察间隔，区分“模型等待”“网络异常”“收益停滞”，以连续证据确认完成；若速度或调用量不合适，继续使用本地识别，或另行适配 Linux 文字识别工具。

## 5. 三个小阶段

每阶段独立验收；用户确认后再做对应的本地 Git 提交。三阶段代码和部署配置均已完成；手机实测与平台验证范围见文末。

### 第一阶段：只识别，不操作

复用已有模型设置与接口，增加独立的截图识别检查。将取图与本地文字识别拆开，纯视觉检查能够在没有 Swift、没有 `bin/ocr` 时运行。

样本覆盖：正常页面、加载或网络异常、遮挡弹窗、相似按钮、小字计数、尺寸与方向变化。人工标注预期结果；保留一组未用于调整提示词的截图作为验收样本。

验收：

- 能返回页面判断、目标位置或计数；看不清时明确“不确定”。
- 非法坐标、缺字段、服务报错、超时与预算耗尽都有清楚提示，不触发手机动作。
- 记录各类样本的正确、错误、不确定次数，以及耗时中位数和较慢请求耗时；不把“不确定”算成正确识别。
- 与当前本地识别对照，用户确认等待时间与调用量可接受后，再进入自动操作。

### 第二阶段：一个低频任务

选择一个已有任务的有限流程：确认页面、定位一个明确按钮、点击、检查结果。新建工作流版本；固定应用、手机、页面范围和允许区域。原版继续保留。

识别方式先放在该任务的试跑入口，不添加独立模型平台或复杂设置页。复用现有模型选择、执行记录、截图证据及版本试跑机制。

验收：

- 目标页面判断正确，坐标与按钮一致，操作后有明确成功依据。
- 相似页面、遮挡、旋转、页面改变和模型迟到时不误点；关键误点出现一次即不通过。
- 停止、人工接管、断线及重启恢复遵守原有规则；结果不明不补发点击。
- 样本通过后，再对已核验的目标手机进行短流程试跑；用户确认后提交。

### 第三阶段：飞牛部署

核查飞牛处理器架构、glibc、systemd 用户服务、USB 与网络条件，使用对应 Linux 原生包部署；需要容器时再选择 Docker。

| 内容 | 落地要求 |
| --- | --- |
| 安装 | 原生包包含 Linux 后台、静态网页和固定版本 scrcpy 服务端，本机安装 Linux ADB；Docker 镜像包含上述依赖。纯视觉运行不依赖苹果组件 |
| 持久保存 | 数据库、截图、访问凭据、模型密钥与 ADB 配对信息保存在用户目录或容器持久目录；程序更新后可恢复 |
| 手机连接 | 优先选一种方式验收：USB 接飞牛，或由飞牛直接无线连接手机；ADB 与投屏后台共用网络环境 |
| 网页访问 | 配置可信 HTTPS；调整当前仅允许 HTTP／IP 的来源检查，明确允许的网址；任务消息与投屏都支持安全连接 |
| 访问控制 | 当前局域网页面可自动建立会话，不能当作远程登录保护；首版限定可信家庭网络或受控组网，扩大访问前再补明确登录 |
| 后台运行 | 配置自动重启、日志和备份；后台退出能清理投屏；原有暂停任务重启后继续保持暂停 |
| 切换与回退 | 迁移前备份，停止旧后台及定时任务后再启动飞牛；同一手机只由一套工作台调度，回退时先停飞牛 |

验收：Mac 关闭后，飞牛仍能截图、投屏、手动操作，并完成第二阶段已验证的纯视觉任务；HTTPS 下任务状态能更新。断线、服务重启和更新不丢配置，不自动重放未确认动作。连接原模型服务时，截图会发送到该服务，部署前在配置说明中明确。

暂不承诺具体速度提升或全部任务可用。USB／无线、手机型号与浏览器分别记录实测结果；实际调用量决定是否继续推进高频任务。

## 6. 交付边界与下一步

本方案不包含通用自主操作、自动改写工作流、策略库开发、录像，以及后台投屏帧共享。这些能力按各自功能单独推进，见 [V2 方案](v2-plan.md)与 [Aya 参考](aya-reference.md)。

当前开发包含：截图与本地识别拆分、只读识别检查、纯视觉判断与点击、截图样本验证、模型快照与预算、HTTPS 访问适配、Mac／Linux 安装及四平台发行配置。

真实模型已用已核验的荣耀截图完成定位、干扰页面拒绝和数字读取，单项模型耗时约 2.2–3.6 秒；仅说明这组截图的结果，不代表不同页面的普遍准确率。

荣耀的原滑动任务自行完成后，已完成系统设置 WLAN 入口的真实短流程试跑：4 张正反样本通过，运行中使用 3 次模型调用，定位、复查、点击和操作后验证均通过。试跑后返回原应用，Wi-Fi 保持开启。本机保存任务 `vision-settings-wlan@1`，其样本随运行数据保存，不随通用发行包分发。

检查范围：Mac Apple Silicon 原生运行与发行包；Linux x86_64／aarch64 容器中的单元、集成、纯视觉和投屏模拟检查；Linux 正式镜像的启动、重启及数据保留；Mac 与两种 Linux 架构发行包的脱离源码目录启动。

飞牛已在 Debian 12 x86_64 上完成原生部署：iQOO USB 授权、真实截图、视觉模型调用、HTTPS 与加密投屏流通过；重新安装与服务重启保留配置。Mac 已信任自签名服务证书，并打开 HTTPS 工作台。访问入口、证书有效期和维护命令见 [飞牛原生部署](feiniu-native.md)。

剩余检查：飞牛整机重启与 Mac 关机后的完整流程、无线手机连接、浏览器内连续投屏和手动触控；Intel Mac 实机与签名公证。Linux aarch64 仅完成虚拟环境检查；GitHub 四平台发行流程尚未触发。高频任务适配、投屏帧共享与识别提速另行推进。
