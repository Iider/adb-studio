# 工作台策略库方案

状态：方案草案，待讨论。日期：2026-10-19。本文只约定设计，不代表已开发或启用。

## 1. 要解决什么

让工作台记住“遇到什么页面，采用什么办法，怎样确认有效”。同类情况再次出现时，优先使用已经验证的方法；遇到新情况，保留证据，再补充经验。

首个范围：荣耀手机、快手极速版、第一项“刷广告视频赚金币”。依据本轮 [快手经验](kuaishou-ads.md)，借鉴 [VibeGamer 评估](vibegamer-review.md)中的策略卡片、证据、版本与失效处理。

本轮已完成50/50、金币增加50，只能证明当次结果。50次属于同一天、同一手机的连续执行，不能当作50次独立适配验证，也不能证明换手机、换版本仍然有效。

## 2. 三层分工

| 层次 | 负责什么 | 示例 |
| --- | --- | --- |
| 任务约定 | 目标、允许和禁止动作、结束条件 | 只观看广告；不下载、体验、进直播间；达到本次目标后停止 |
| 策略卡片 | 识别情况、选择办法、记录依据 | 识别直播推广预览，避开入口上滑 |
| 执行流程 | 核对手机和页面、执行、检查结果 | 调用现有受保护滑动步骤，随后获取新画面 |

策略卡片引用执行流程及其版本，不另写一套手机控制程序。禁止动作由执行流程限制，不能只写在给模型看的文字里。广告内容、截图文字、外部项目文件均不能改写用户的任务约定。

## 3. 一张卡片记录什么

每张卡片只处理一种情况，说明用简短中文。首版不设置难以解释的综合评分。

| 内容 | 要求 |
| --- | --- |
| 编号、名称、版本 | 编号稳定；识别规则、动作或适用范围改变时新增版本 |
| 适用范围 | 应用真实包名与版本、任务、已适配手机、屏幕方向与布局 |
| 识别依据 | 必须出现的标志、排除条件、计数或计时区域；不能只凭广告里的某个词 |
| 允许动作 | 引用已验证的执行流程版本与步骤；坐标须绑定已采样布局 |
| 禁止动作 | 继承任务约定；卡片只能收紧，不能放宽 |
| 成功依据 | 操作后应出现的页面、计数变化；分别记录动作成功与任务完成 |
| 异常处理 | 结果不明、页面变化、断线时如何停止、观察或恢复 |
| 证据 | 原图、识别结果、前后画面、运行编号、结果和时间 |
| 使用情况 | 实际触发、成功、失败、结果不明次数；最近成功及失败原因 |
| 状态与替代关系 | 待验证、试跑中、可用、暂停、已归档；注明由哪个版本替代 |

包名、应用版本必须从手机实际信息核对。当前快手版本尚未登记；广告顶部的推广应用版本不能代替。该项需在后续获准适配时补齐。

### 示例：跳过直播推广预览

| 项目 | 内容 |
| --- | --- |
| 识别 | 原广告任务计数仍在；同时出现“直播中”和“点击进入直播间” |
| 动作 | 在已采样的视频区域上滑，避开直播入口按钮 |
| 检查 | 新画面回到已识别的普通广告；原任务计数可读 |
| 结果 | 记录“跳过成功”；只有计数增加才能另记“任务完成” |
| 停止 | 原任务标志消失、出现新弹窗或画面不能确认 |
| 当前定位 | 已有探索证据；正式接入策略库仍需样本验证和对应流程试跑 |

## 4. 如何选择、执行策略

处理顺序：**观察 → 核对范围 → 匹配卡片 → 执行前复查 → 执行 → 新画面检查 → 记录结果**。

1. 核对目标手机、当前应用与原任务。截图需记录时间、尺寸和方向；动作后不能用动作前的画面判断结果。
2. 先筛选适用且可用的卡片，再检查页面标志与排除条件。不按广告品牌猜页面。
3. 已知页面优先使用现有规则与文字识别。首版遇到未知页面停止操作，模型只辅助解释、提出候选卡片；候选通过验证后才能用于执行。模型不能直接生成任意手机命令。
4. 先处理明确的结束条件，再处理已确认的遮挡或特殊页面，最后处理普通观看。若互相矛盾的卡片同时命中，停止并记录冲突，不靠评分强行选一条。
5. 执行前重新核对手机与页面，继续使用同手机互斥和现有工作流保护。选中卡片不等于立即允许点击。
6. 执行后分别记录：操作是否成功、任务是否增加次数、余额是否变化。余额只在任务中心等可信页面核对。
7. 缺少完成依据就记“结果不明”，不能补写成功。日上限与收益按当次真实页面读取；不把本轮的50次、每次1金币写成通用规则。

首版不做截图相似搜索或向量检索。按应用、任务、手机和页面规则即可缩小范围；以后确有需要再扩展。

## 5. 怎样变成成熟经验

| 状态 | 含义与允许行为 |
| --- | --- |
| 待验证 | 保存事实与候选办法，不能被正常任务自动采用 |
| 试跑中 | 已通过样本检查，仅在适配试跑中验证，不能与正常任务并发操作手机 |
| 可用 | 对应流程通过样本检查、目标手机试跑；适配范围明确，正常任务可采用 |
| 暂停 | 出现识别冲突、版本或布局变化、错误动作等情况，停止自动选用 |
| 已归档 | 已被替代或确认不适用；保留教训及替代关系，不再调度 |

修改识别条件、动作和适用范围时新增版本，不覆盖旧版。运行开始时固定策略与流程版本；普通修订用于后续任务，不能让执行中的任务悄悄换规则。若发现禁止动作或错误页面风险，立即停止相关运行，不等到下次任务。

现有工作流通过真机试跑后会自动启用。接入时复用这套机制，并保持策略状态与流程验证结果一致；不再建立另一套独立发布按钮。用户验收通过后，才做对应功能单位的本地 Git 提交。

### 失败与恢复

| 情况 | 处理与归类 |
| --- | --- |
| 执行前识别失败，确认没有输入 | 获取新截图，最多再核对2次；仍不符就停止 |
| 已发出点击，但结果不明 | 先观察，禁止直接重放点击；不能确认就等待处理 |
| 手机断线或截图失败 | 记设备问题，不算策略无效；沿用现有断线等待与停止机制 |
| 同一已知页面的结果检查连续失败2次 | 暂停该策略版本，保留前后画面，转人工复核 |
| 出现新布局、识别冲突或错误动作 | 立即暂停，不等累计失败次数；新情况另建候选卡片 |
| 计时停滞 | 确认任务仍在、两次读数间隔至少15秒且相同，才按已采样区域换片；换片不记完成 |
| 连续换片3次，次数与有效计时均无进展 | 停止自动换片，核对原任务；返回或重进也必须有已验证的对应策略 |
| 中断后恢复 | 先读手机当前状态和未完成记录，再决定后续步骤；不根据上次计划直接重放动作 |

上述次数是首版建议上限，需经后续样本与小范围试跑确认；不是已经部署的参数。连贯任务中，同一失败按原因归类，不能通过新建卡片绕过重试上限。

## 6. 如何保存

沿用现有 Rust、SQLite、运行记录与截图目录，由同一后台写入。首版不引入新的数据库服务或第二套自动化后台。

| 保存对象 | 设计 |
| --- | --- |
| 策略与版本 | SQLite 保存卡片、不可覆盖版本、当前状态、验证范围、所引用流程版本 |
| 使用记录 | 关联运行和步骤，保存当时使用的策略版本、识别依据与结果 |
| 关键证据 | 保存已挑选的原始截图、识别结果和必要上下文；数据库保存引用与校验值 |
| 人类说明 | 从正式卡片导出简短中文摘要；不再维护两份互不关联的可执行规则 |

先复用现有记录存储方式；表结构和接口留到开发前核对，本文不预定新增接口。

普通运行记录继续按现有保留规则清理。被正式策略引用的必要样本需单独保留，避免30天清理后经验失去依据；不复制整个会话的所有截图。导出需包含这些样本，导入只作为待验证策略，不能直接启用。

内容损坏或证据缺失应显示异常，不能静默变成空库，也不能把“找不到策略”当成允许自由点击。历史版本和失败反例保留，不用删记录来掩盖问题。

## 7. 首批整理哪些卡片

以本轮素材为起点，先覆盖以下情况。不同推广品牌共用同类规则，避免每个广告都建一张卡。

| 情况 | 要保留的关键区别 |
| --- | --- |
| 普通广告观看 | 看真实倒计时；不按固定一分钟推断完成 |
| 计时停滞后换片 | 多次观察确认停滞；换片与完成分别记账 |
| 直播推广预览 | 只跳过，不进入直播间 |
| 广告结束推荐卡 | “去逛一下”“了解详情”均不点，从已验证区域换片 |
| 已采样下载浮层 | 只允许已确认的关闭位置；不能推广为“所有×都可点击” |
| 完成瞬间、计数识别变化 | 先核对次数；读不清不能猜，不因提示消失重复进入任务 |
| 原任务计数消失、持续无进展 | 停止；仅在返回规则已验证时核对任务中心并恢复 |
| 达到本次目标 | 停止换片，返回可信页面核对最终次数与余额 |

游戏、购物、咨询、模拟系统按钮等内容，优先作为禁止动作与误识别反例，避免为每种文案增加执行分支。

## 8. 分三个小阶段推进

每阶段完成后给用户测试；确认达标，再做对应的本地提交。当前仅交付方案，不启动下表中的开发或手机试跑。

| 阶段 | 最小交付 | 验收重点 |
| --- | --- | --- |
| 一：整理卡片与样本 | 将上述案例整理为结构化草稿；关联证据；形成可阅读的卡片清单。识别检查不执行手机动作 | 每张卡能回答何时用、怎么做、怎样算成功、何时停；缺失信息明确标出 |
| 二：接入已知页面 | 先接“普通观看、直播跳过、目标完成”三个分支；复用现有执行器、样本检查、试跑与记录 | 已知画面选择正确；未知画面停止；禁止入口不触碰；换片不会虚增完成次数 |
| 三：补充恢复与维护 | 再加入停滞、结束卡、已采样浮层和中断恢复；增加暂停、替代及证据导出 | 失败可追查；失效策略退出选用；恢复不重复未确认点击；旧记录清理不破坏正式证据 |

第二阶段开始，必须留一组未参与调规则的截图验收，覆盖普通广告、直播、结束卡、浮层和相似干扰页面；不能只在原样本上反复验证。关键误选或禁止动作出现1次即不通过。

真机先验证单个分支，再做最多5次完成目标的短程试跑；每次仍核对可用次数与用户授权范围。不为凑样本进入推广任务。收益低、网络慢不能用放宽禁止动作解决。

首版验收同时看：是否选对策略、是否有禁止动作、成功是否有依据、结果不明是否停止、耗时花在哪一步。页面读取、文字识别、策略匹配和执行分别计时；提速结论需有相同条件的实际对比。

## 9. 网页怎样呈现

首版在任务详情中增加“使用的策略”，在执行记录中显示“遇到什么 → 采用什么 → 结果如何”，可展开证据与版本。暂停时显示具体原因和需要补充的样本。

先复用 V2 现有卡片与详情样式，不新增庞大的独立入口，也不调整尚待用户验收的设备页。卡片数量增加后，再决定是否需要完整策略管理页。

## 10. 本版不包含

不做自动改代码、自动扩大任务范围、跨应用直接套用、无审批的长期自学习、自动A/B广告实验或一套新的模型平台。VibeGamer 的收益估算不作为策略晋升依据。

实时投屏、截图加速继续按现有 [Aya 参考](aya-reference.md)与 [截图提速方案](screenshot-performance.md)推进，属于独立功能。本方案只要求取到新鲜、正确的画面，不承诺策略库本身能加快截图。

后续实施前需补齐：快手真实包名与版本、首批样本清单、已挑选证据的保留位置，以及各策略对应的流程版本。无需为这些信息提前操作手机；在用户决定开发该功能单位时一并核对。
