# Aya 实时控制参考

源码：`/Volumes/SSD/手机自动化/references/aya`。上游 https://github.com/liriliri/aya ，检查版本 1.14.2，提交 `44c02f7`。Aya 投屏部分为源码分析；截图基线通过现有工作台测量。

## 已确认的实现

- Electron + React 桌面应用；不是直接面向远程浏览器的站点。
- 主进程通过 adbkit 推送 scrcpy 3.1 服务端，用 `app_process` 启动。
- 通过 ADB reverse 和本机 TCP 连接接收视频、音频与控制流；当前投屏模块没有提供浏览器 WebSocket 转发接口。
- 前端使用 `@yume-chan/scrcpy` 解析协议，使用 `@yume-chan/scrcpy-decoder-webcodecs` 解码 H.264 视频。
- 普通截图调用 adbkit 的 `device.screencap()`；投屏窗口的截图调用 `video.decoder.snapshot()`，直接从已解码的视频画面生成图片。这是两条独立路径。
- 触控按下、移动、松开通过控制流发送。坐标换算考虑画面比例和留白；鼠标右键、滚轮、键盘另有对应处理。
- 支持投屏时保持唤醒，以及关闭物理屏幕的独立指令。物理屏幕关闭与系统锁屏不是同一种操作，需要分别验证手机兼容性。

关键源码：

- `src/main/lib/adb/scrcpy.ts`：手机端启动。
- `src/renderer/screencast/lib/ScrcpyClient.ts`：连接、视频解码、触控、坐标换算。
- `src/renderer/screencast/store.ts`：投屏配置与保持唤醒。
- `src/renderer/screencast/components/Toolbar.tsx`：投屏画面截图。
- `src/main/lib/adb.ts`：普通截图、电量与内存读取、设备连接变化监听。
- `script/scrcpy.mjs`：服务端版本来源。

## 优先复用的部分

| 能力 | 复用方式 | 工作台用途 |
| --- | --- | --- |
| scrcpy 视频协议、浏览器解码 | 引入底层库，补上 Rust 到浏览器的视频转发 | 实时预览与从视频画面截图 |
| 点击、拖动、留白区域的坐标换算 | 参考逻辑，适配 Svelte 与现有手机核验 | 手动控制与位置标注 |
| 电量、温度、内存、CPU 数据读取 | 参考命令与解析规则，保留机型兼容检查 | 将 V2 模拟指标替换为真实数据 |
| 设备连接变化监听 | 参考事件驱动方式，保留重连与恢复机制 | 减少重复枚举设备 |
| 录像 | 参考复用同一视频流的方式 | 后续保存任务执行片段 |

Aya 的 Electron、React、MobX 页面和桌面消息接口需要移植，不宜整体并入当前 Rust 与 Svelte 工作台。文件管理、应用管理、终端等功能与本次截图提速关系较小。

## 截图耗时基线

2026-10-18，荣耀 `ASK-AL00x`，USB，截图尺寸 720 × 1560，手机同时有工作台任务执行。顺序调用现有截图接口三次，不包含网页渲染、文字识别或模型调用。

截图耗时中位数为 1.757 秒。对第三张图片使用现有已编译 OCR 程序重复识别三次，耗时为 0.473、0.252、0.255 秒，包含识别进程启动；不包含取图。该组数据中，截图比本机文字识别更耗时。其他手机、无线连接和不同页面需要分别测量；投屏截图尚未做真机速度对比。

## 截图提速建议

现有截图路径已增加分段计时、同次截图连接核验复用、USB 原始画面取图，以及识别图片复用。实测结果见 [截图提速与验收](screenshot-performance.md)。每次请求仍获取新画面；手机身份、亮屏与图片完整性检查保留。

投屏运行时，直接读取最新已解码画面，通常能减少单次截图的额外等待。仅打开 Aya 投屏，而工作台继续调用原截图接口，不会自动获得这项收益。临时为一张截图启动投屏，还需要计入连接、编码器启动和首帧等待。

工作台适合采用两条取图路径：

- 普通截图：保留现有 ADB 原图路径，用于未开启投屏、精细文字识别、重新标注和异常回退。
- 快速取图：由后台管理视频流与最新解码画面，供网页、截图和识别共享。自动任务需要时可独立保持图像流，网页关闭后仍能取图。

快速取图需要记录画面时间、序号、尺寸及屏幕来源。动作后的结果检查应使用更新画面；无法确认画面已更新或流已中断时回退原图。旋转、折叠屏切换和重连后，清除旧画面并重新确认屏幕与坐标。

视频画面可能经过缩放及有损压缩，即使另存为 PNG 也不会恢复原始细节。小字、金币数字和精确图像判断需对照原图验证；持续投屏还会增加手机编码、电脑解码和传输开销，按需要启用。

## 工作台接入建议

沿用 Rust、Svelte、SQLite。复用 scrcpy 协议和解码库；Rust 管理手机端服务、ADB 通道和 WebSocket 转发，Svelte 展示实时画面与操作按钮。

手机卡片增加“实时控制”。先进入只看画面模式；申请手动控制时与自动化使用同一台手机的互斥锁，退出或连接中断时释放控制并处理未松开的触点。不能自动重启已经停止的任务。

首次实现聚焦单机画面、点按、拖动、返回、主页、唤醒和断线清理。音频、剪贴板、录像后续再加。折叠屏沿用当前亮屏选择逻辑，实际验证切换屏幕与旋转后的画面尺寸及触控映射。

远程浏览器使用 WebCodecs 需检查安全上下文和浏览器支持；当前局域网 HTTP 地址不能视作所有浏览器都可用的最终投屏地址。外网访问优先通过组网工具连回家中 Mac，并提供 HTTPS 和明确登录，不直接暴露 ADB 端口。

Aya 为 AGPL-3.0。若复制或改造其源码，需要遵守相应许可；优先直接使用各自许可明确的 scrcpy 和协议库，接入前核对具体版本许可并更新来源声明。

已核对本地 Aya 所声明版本的底层组件许可：scrcpy 3.1 为 Apache-2.0；`@devicefarmer/adbkit` 3.3.8 为 Apache-2.0；`@yume-chan/scrcpy` 1.1.0、`@yume-chan/scrcpy-decoder-webcodecs` 1.1.0、`@yume-chan/stream-extra` 1.0.0 为 MIT。adbkit 面向 Node.js，当前 Rust 后台可参考其连接方式，无需为截图另加一套 Node.js 后台。

本次源码分析不能证明先前的 INJECT_EVENTS 错误由 Aya 造成。接入时通过独占控制避免并发操作，真机验证触控权限错误及恢复行为。
