## 目标与范围

把工作流保存为一个文件，供备份、迁移和分享；导入后仍可编辑和运行。

- 首版采用单个 `.workflow.json` 文件，每个文件包含一项任务，可携带画布草稿和引用的图片样本。
- 支持画布任务、旧格式任务、纯视觉任务，以及尚未完成的画布草稿。
- 每项任务仍只有一份本体，保存直接覆盖。导入不产生历史版本或自动快照。
- 保留现有运行规则：保存后直接运行；样本检查自选；条件判断的页面依据默认空，留空跳过页面确认。
- 导入只保存内容，不自动运行、不操作手机，不创建或开启定时。

首版不做批量文件、ZIP、云同步、分享链接或跨格式自动转换。

## 页面入口

| 位置 | 操作 | 内容 |
| --- | --- | --- |
| 自动化任务页标题右侧 | 导入工作流 | 选择文件，预览后导入 |
| 所有任务卡片的“更多” | 导出工作流 | 导出当前本体，并携带存在的关联草稿 |
| 画布编辑器的“更多” | 导出当前草稿 | 导出当前编辑内容，包括尚未完成的步骤 |

任务页只增加一个次要按钮；卡片操作放进现有菜单。沿用现有弹窗遮罩模糊、阴影、按钮高度及窄屏布局，不新增常驻说明栏。

导入弹窗显示名称、步骤数、内容类型、适用手机、图片数量和需要处理的问题。默认“新建副本”；选择“覆盖已有任务”时，再选择目标并明确显示其名称。确认按钮分别使用“导入副本”和“覆盖此任务”。

导入成功后，任务文件提供“编辑任务”；纯草稿文件直接打开对应画布。运行仍使用现有入口，导入过程不附带运行。

## 导出内容与草稿差异

本体是下次运行采用的内容；草稿可以含有尚未手动保存的编辑。文件必须分别记录两者，不能把较新的草稿冒充已保存任务。

### 从任务卡片导出

- 必须包含当前本体；存在关联草稿时一并携带名称、节点、连线、配置、位置与视野。
- 草稿与本体不同或草稿尚未完成时，下载前提示“文件同时包含已保存任务和待保存编辑”。导入后保留两份内容的原有关系，手动保存草稿才覆盖本体。
- 用草稿编译结果与本体比较，按结构比较并忽略设备列表顺序，不依赖对象字段顺序；编译失败视为未完成草稿。
- 没有草稿时只导出本体。导入后沿用现有任务表单编辑，不承诺恢复不存在的画布布局。

编译会清除节点位置，结束节点也会转换为执行动作。因此不能仅凭本体恢复原画布，更不能导出时用草稿重新编译并替换本体。

### 从画布编辑器导出

- 先调用现有 `flush()` 保存当前编辑，再读取对应校对编号的草稿。
- 只导出草稿，`workflow` 为 `null`；不强制执行完整运行校验，不顺带覆盖本体。
- 自动保存失败、存在恢复冲突或草稿已被其他页面修改时，保留页面编辑，提示处理后重试；不静默下载旧内容。
- 导入后仍是草稿。完整时可按现有“保存”生成任务；未完成时继续编辑。

## 文件格式

文件使用 UTF-8 JSON。建议下载名为 `<任务名称>.workflow.json`，清除路径分隔符与系统不允许的文件名字符。

下面是只有本体的最小示例：

```json
{
  "format": "adb-studio.workflow",
  "format_revision": 1,
  "content": {
    "workflow": {
      "schema_version": 1,
      "launch_mode": "standard",
      "id": "wait-once",
      "name": "等待后结束",
      "description": "在当前页面等待两秒。",
      "devices": [],
      "entry": "wait",
      "model_limit": 10,
      "recognition": "local",
      "nodes": [
        {"id": "wait", "label": "等待两秒", "type": "wait", "seconds": 2, "next": "end"},
        {"id": "end", "label": "完成", "type": "end", "result": "succeeded"}
      ],
      "tests": []
    },
    "draft": null
  },
  "assets": []
}
```

| 字段 | 规则 |
| --- | --- |
| `format` | 固定标识，避免把执行记录或其他 JSON 误当工作流 |
| `format_revision` | 文件格式编号；用于判断能否读取，不是工作流历史版本，页面不展示版本选择 |
| `content.workflow` | 当前 `Workflow` 结构或 `null`；字段说明见[工作流接口](workflows.md#工作流格式) |
| `content.draft` | 可移植草稿或 `null`；两项不能同时为空 |
| `assets` | 被内容引用的 PNG 样本，空时为 `[]` |

可移植草稿只含 `id`、`name`、`description`、`entry`、`nodes`、`viewport`。节点沿用 `DraftNode` 的 `id`、`kind`、`label`、`config`、`targets`、`position`。草稿的 `revision` 与 `updated_at` 由导入服务生成，不进入文件。

同时包含两者时，来源本体编号必须为 `manual-<来源草稿 UUID>`。草稿和本体可以有内容差异，但必须属于同一任务。

每项图片为 `{"id":"来源样本UUID.png","mime":"image/png","base64":"纯PNG的Base64内容"}`。保留所有原样本引用，导入时统一替换为本机生成的新文件名。

文件包含步骤中的文字、应用包名、手机自身编号与标注位置；导出提示这些内容会随文件分享。使用字段白名单构造文件，不打包数据库或整个数据目录，不加入模型密钥、访问令牌、ADB 地址与配对信息、执行记录、运行截图、定时状态。用户自行写进步骤参数的内容按原样保存。

## 导入规则

### 新建副本：默认方式

- 不按文件里的来源编号直接覆盖。即使同名或重复导入，也新建独立副本。
- 有草稿时生成新 UUID，本体编号统一为 `manual-<新UUID>`；只有本体时生成 `import-<新UUID>`。
- 保留节点编号及所有内部引用，包括 `entry`、`next`、`targets`、`config.loop` 和样本的 `node`；这些编号只在各自任务内部使用，无需重编。
- 同名时建议名称“原名称（导入）”，用户可在预览中改名；遵守现有名称长度限制。分别保留本体和草稿原有名称差异。
- 新任务不携带定时或运行状态。

### 内置任务的运行方式

工作流增加可选 `launch_mode`：`standard`（按步骤执行）、`device_point`（运行时采用目标手机的点击标注）、`swipe_settings`（提供滑动时长与间隔设置）。旧数据缺省时按原 `point-click`／`swipe` 编号识别；导出必须写明实际方式，导入及覆盖后保留明确值，不能用新编号重新推断。

- 后台运行、屏幕恢复检查、设备详情、任务卡片、定时表单和普通任务编辑共用相同判断。只有旧数据兼容读取允许按编号回退。
- `device_point` 只接受含固定点击步骤且不含画布步骤的本地任务；`swipe_settings` 只接受含滑动循环且不含画布步骤的本地任务。保存时验证方式与步骤相容。
- 手机的点击标注属于本机设备设置，不随模板导出；导入预览说明该依赖。选择手机后沿用标注入口；缺少标注时不执行默认坐标。
- 普通任务覆盖到内置编号时，明确的 `standard` 应覆盖旧编号的默认行为；内置副本仍保留自己的运行方式。

### 覆盖已有任务：明确选择

- 仅接受含本体的文件。纯草稿按新草稿导入，避免意外清除现有可运行任务。
- 预览说明“将替换当前任务内容和关联草稿；已有定时下次使用新内容”。不生成备份或快照。
- 目标编号保持不变，既有定时和执行记录保留。已启动任务按启动时内容继续运行。
- 为减少迁移改动，首版仅允许同类覆盖：有草稿的文件覆盖有草稿的画布任务；只有本体的文件覆盖没有草稿的任务。跨类导入使用新建副本。
- 预览返回目标内容校验标识，涵盖本体、草稿及其 `revision`。确认时重新核对；任何一项变化都返回 409，要求重新预览，不能悄悄覆盖其他页面的编辑。
- 覆盖草稿沿用目标 UUID，递增目标当前 `revision`；旧编辑器随后自动保存会收到冲突，必须保留页面内容并提示重新读取或保存副本。
- 没有草稿的任务表单已通过 `If-Match: *` 防止重建已删除的任务；同一单位仍需补上读取时的内容校验标识，保存时核对是否被其他页面修改。否则导入后的内容仍可能被旧表单覆盖。

### 手机与图片

- 保留 `devices`、`profiles`、条件 `regions` 中的手机自身编号、宽高、显示屏标识和坐标，不使用无线连接地址代替编号。
- 手机离线或本机尚未登记该手机时，允许导入，提示“原手机未连接／未登记”。不把坐标自动套用到另一台手机。
- 更换手机或屏幕形态时，使用现有标注入口重新取图标注；实际运行仍沿用现有适配检查，不新增试跑或启用门槛。
- 首版不做一键换绑、坐标缩放或新增设备映射表。
- 导出收集 `tests.image` 引用的 PNG；漏失任一图片时，提示具体样本并停止导出，不静默丢弃检查样本。用户可在编辑页移除失效样本后重试。
- 导入检查引用是否完整，拒绝缺图和多余附件。只接受 PNG 文件名标识，不接受本机绝对路径、目录跳转或网络下载地址。
- 导入只检查结构与图片，不调用识别模型。目标机器使用本机模型配置；缺少配置时沿用现有设置提示。

## 新增接口提案

两个导出接口已实现，两个导入接口待实现；均复用现有访问令牌、同源限制与错误格式。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/workflows/{id}/export` | 一致读取本体、关联草稿和图片，返回文件下载 |
| `GET /api/workflow-drafts/{id}/export?revision=...` | 校对编号一致时导出草稿文件，否则返回 409 |
| `POST /api/workflow-import/preview` | 接收文件与导入方式，校验并返回摘要、手机提示及覆盖校验标识；不写入 |
| `POST /api/workflow-import` | 接收同一文件、导入方式和覆盖校验标识，重新校验后原子保存 |

预览与确认共用一套解析和校验函数。服务端重新计算步骤数、设备列表与问题摘要，不信任浏览器的“已检查”标记；用户改名作为独立输入重新校验。接口返回新建或覆盖后的任务编号、草稿编号及提示，前端按返回值跳转。

### 校验与失败处理

- 入口区分可移植文件与裸 `Workflow` JSON；首版也接受符合当前结构的裸工作流，按“只有本体”处理，带图片引用但未携带图片时说明原因并拒绝。
- 拒绝不支持的文件格式编号、未知外层字段、未知动作、重复节点、越界数据和不完整图片引用，不静默忽略含义不明的内容。
- 草稿复用 `drafts::validate`，允许现有自动保存可接受的未完成编辑；本体复用 `engine::validate`。不把完整执行校验强加给纯草稿，不进行样本诊断或试跑。
- 导入文件及请求体上限为 32 MiB；正常编辑接口保留 2 MiB 限制。本体与草稿分别重新序列化后不得超过 `2 MiB - 1024 字节`，为服务字段和后续编辑请求预留余量；导出执行相同检查，避免下载一个无法导回或编辑的文件。超限时保留内容并说明原因。
- 最多 40 张 PNG，Base64 还原后合计不超过 20 MiB；单张直接复用 `vision::decode`，沿用不超过 8 MiB、宽高各不超过 8192、解码内存 128 MiB 的规则，逐张处理。不另设更窄的单张像素限制。最终 JSON 连同附件不超过 32 MiB。
- 图片在独立阻塞任务中限量解码、验证，再以新 UUID 文件名保存；不信任文件名、MIME 或声明尺寸。
- 建议错误状态：400 内容无效、404 目标不存在、409 内容已变化、413 文件超限、422 文件格式不受支持。说明定位到步骤或字段，例如“第 3 步：下一步指向不存在的节点”。
- 校验或写入失败时，本体、草稿、定时与执行记录都不得部分改变。确认按钮提交中禁用；网络结果不明时保留同一次操作编号，以同一编号重试。

### 保存一致性

在 `Store` 增加面向导入的事务方法，事务中检查覆盖条件并同时写本体、草稿。已有保存接口不增加历史记录。

浏览器在用户发起一次导入时生成 `operation_id`（UUID），预览、确认与网络重试保持该编号。服务在 `workflow_imports` 中保存请求摘要与结果，并与本体、草稿一起提交；同编号同内容返回原结果，同编号不同内容返回 409。另一次主动导入生成新编号，仍可新增副本。图片目标文件名在同次操作内保持一致，重试不得重复生成附件；查询原结果的检查先于覆盖冲突与图片写入。操作记录用于确认提交结果，不保存旧任务内容；目标后来已删除时明确返回原操作已完成、目标已移除。

图片先写临时目录，校验成功后以新文件名移入样本目录，再提交数据库；失败清理本次新增文件。进程意外退出可能留下无引用图片，但不能提交引用缺图的任务。临时文件和无引用导入图片应有清理测试，清理不得删除其他任务使用的样本。

导出从同一数据库读取事务获取本体与草稿；涉及保存、删除或运行启动时沿用现有互斥顺序。若同时需要定时锁与运行锁，保持 `schedule_gate → run_gate`，文件解码放在持锁前。事务提交后再发一次 `changed` 通知、刷新列表。

## 开发顺序与验收

每个单位先完成自动检查与隔离模拟检查，再请用户在网页测试；用户确认后做对应本地 Git 提交。隔离测试使用临时数据库和其他端口，不重启或改动正在使用的服务；正式部署按当次授权执行。

| 单位 | 内容 | 用户验收重点 |
| --- | --- | --- |
| 1. 文件与导出 | 运行方式兼容、格式、两处导出入口、图片收集 | 画布任务、普通任务、视觉任务都能下载；草稿布局和待保存编辑完整；重复导出不改变任务 |
| 2. 导入副本 | 预览、手机提示、事务保存 | 导回文件后可编辑；原任务不变；手机离线也能导入；完整任务无需试跑即可运行，未完成草稿可继续编辑 |
| 3. 覆盖导入 | 目标选择、冲突校验与明确确认 | 只覆盖选中目标；已有定时保持；旧页面编辑冲突不丢内容；不产生版本或快照 |

自动检查至少覆盖：

- 导出再导入后，步骤参数、分支、循环引用、页面依据空值、坐标、文字区域、画布位置和视野保持一致；仅外层任务编号、草稿编号、图片文件名按规则更换。
- 本体和草稿不同、草稿未完成、缺草稿的画布本体，以及普通／视觉任务分别往返，保留原有编辑方式和运行内容。
- 同名文件重复导入产生独立副本；覆盖时定时仍指向目标编号，已启动任务不受影响。
- 预览后目标内容被其他页面修改时返回冲突；目标删除时返回不存在。画布旧页面自动保存与普通任务旧表单提交都不能覆盖导入内容。
- 非法文件、未知动作、无效坐标、错误循环、缺图、伪 PNG、路径跳转、超大图片和请求超限都给出可读提示；失败不留半份任务。
- 模拟图片写入失败、数据库提交失败及重复点击；模拟提交成功但响应丢失，同次重试只产生一项任务和一套图片。
- 内置定点点击和定时滑动往返后仍保留标注、运行参数、定时参数与恢复检查；普通内容覆盖内置编号后不继承错误行为。
- 检查本体和草稿接近正常保存大小上限，以及现有读取规则允许的较大 PNG；每个成功导入的内容都能继续编辑保存。
- 使用现有前端检查与构建、Rust 测试及隔离接口检查；页面分别核对日夜模式、窄屏、键盘操作和导入失败后继续编辑。
