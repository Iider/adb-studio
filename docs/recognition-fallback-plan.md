# 模型配置与自动读字整改方案

状态：待实施。日期：2026-10-28。本方案不表示功能已经上线。

## 目标

没有安装本地读字工具时，模型接替读字。用户继续使用现有“页面文字 → 包含文字／不包含文字”和框选区域，不需要另建纯视觉工作流。

设置页直接填写服务地址、模型名称和 API Key，能够保存、查看配置状态，并用内置样图测试是否支持看图。Mac、Linux、Windows 使用同一套选择规则，保留已有本地工具和环境变量配置。

## 调查结果

| 问题 | 当前实现与证据 | 结论 |
| --- | --- | --- |
| 填写 Key 后无法保存 | 页面将输入提交为 `key_env`；`src/api.rs::set_model` 只允许字母、数字、下划线 | 此字段是环境变量名称，不是真实 Key 输入框。常见含连字符的 Key 会被拒绝；即使字符串恰好通过校验，也只是把它保存成变量名，仍不能正确调用模型 |
| Base URL 是否导致保存失败 | 隔离服务使用截图中的 HTTPS 地址和 `MODEL_KEY`，返回 200；使用模拟 Key 作为 `key_env`，返回 400“模型或密钥变量无效”，原配置不变 | 保存错误首先来自密钥字段的用途与用户预期不一致，不能只调整地址来解决 |
| 保存地址后是否能调用 | `src/recognition.rs::request` 直接向 `endpoint` 发 POST，不补接口后缀 | 当前要求完整接口地址；只填 Base URL 可能在调用时失败。保存成功不等于连接或看图成功 |
| 页面文字是否自动用模型 | `src/canvas.rs::observe` 调用本地 `recognition::frame`；文字条件在启动时检查本地 OCR 是否可用 | 当前没有统一的模型读字替代能力；仅添加 Key 输入框不够 |
| 为什么失败原因不明显 | 保存错误只用短时通知显示；条件观察将读字错误转成 `None` | 用户难以分清字段填写错误、模型不可用和页面看不清 |

复现使用隔离数据库、模拟 ADB 和虚构 Key，未修改正式设置、未调用外部模型，也未读取截图里隐藏的真实 Key。正式后台仍保存默认完整接口地址，`key_env` 仍为 `MODEL_KEY`。

截图中的 Coding 服务地址、所选模型是否允许图片输入及支持哪一种接口，尚未通过真实调用确认。不能仅凭能保存 HTTPS 地址，就认定该服务可用于手机看图。

任务范围：仅工作流编辑器任务及其条件；旧内置任务、旧纯视觉动作、金币与汽水专用功能不再兼容。环境变量密钥配置继续保留。

## 一、先修复模型设置

### 页面

主表单提供三项：

| 字段 | 行为 |
| --- | --- |
| 服务地址（Base URL） | 接受 Base URL，也兼容已填写的完整接口地址 |
| 模型名称 | 使用服务商实际支持的模型编号；读字替代要求模型支持图片 |
| API Key | 密码输入框，直接填写真实 Key；已有 Key 只显示“已配置”，不回填原值 |

接口格式保留 Responses／Chat Completions 选择，放入高级设置。原 `MODEL_KEY` 等环境变量方式也放入高级设置，供已有部署继续使用，不让普通用户把真实 Key 填进变量名称。

- 空白 Key 表示保留已有 Key；清除 Key 使用单独、明确的操作，不能把留空当成删除。
- 自动保留 Key 只适用于同一服务。更换规范化后的服务来源（协议、主机、端口或基础路径）时，可保存为待配置、填写新 Key，或通过明确的“将现有 Key 用于新服务”选项授权沿用。没有可用 Key 或尚未确认沿用时，不发测试或识别请求。
- 保存成功显示持续可见的“已保存／密钥已配置／识别连接未验证”；字段错误显示在对应字段附近，保留填写内容。
- “保存设置”只做校验和本机保存，不等待模型返回；另设“测试识别”，结果保留到下一次测试。
- 测试使用内置文字样图，验证图片请求及返回结果，不读取手机当前画面。页面说明测试会调用模型。
- 测试只针对已保存的设置；有未保存修改时提示先保存。结果绑定设置修订号及服务端实际解析的凭据指纹，地址、模型、接口或 Key 变更后失效，包括外部修改 `.env`；指纹不对外返回。迟到的旧测试结果不能把新配置标成“通过”。通过只表示该次样图测试成功，不保证服务持续在线。

### 地址处理

服务端统一处理地址，前端不另写拼接规则：

| 输入及格式 | 请求地址 |
| --- | --- |
| `https://example.com/v1` + Responses | `https://example.com/v1/responses` |
| `https://example.com/v1/` + Chat Completions | `https://example.com/v1/chat/completions` |
| 已含 `/responses` 或 `/chat/completions` 的完整地址 | 保留完整地址，不重复拼接 |
| 自定义的完整接口路径 | 高级设置选择“完整接口地址”，按原路径请求，不追加后缀 |

输入完整地址却选择另一种接口格式时明确提示，不悄悄改写。保留现有 HTTPS／本机 HTTP、禁止 URL 用户名密码、禁止重定向等限制。旧设置仍按完整 `endpoint` 读取；新设置保存规范化后的实际请求地址，供原有请求代码和任务快照使用。

新设置区分 `base` 与 `full` 地址方式；旧数据缺少该字段时按 `full` 读取，打开后原样保存也不追加路径。Base URL 由 URL 解析器追加路径片段，保留基础路径，不能用会丢弃基础路径的根路径拼接。规范化仅用于明确的尾斜线、默认端口等处理，不猜测自定义完整路径。

服务商使用不同路径或不支持某种接口时，通过测试报告具体问题，不按域名猜测支持能力，不自动更换模型。

### Key 的本机保存

- 新 Key 只通过已鉴权的设置请求传入，写入 `data/` 下的私有密钥文件；禁止进入数据库正文、日志、运行记录、导出文件和浏览器持久存储。
- 新 Key 去掉首尾空白、拒绝换行和 NUL，不能沿用环境变量名称的字符限制；普通 Key 中的连字符、加号和等号等内容不因此被拒绝。
- 模型设置只保存密钥引用及来源，不保存 Key 明文。Windows 复用当前用户权限限制，Mac／Linux 使用私有目录和 `0600` 文件权限。
- 设置请求与公开响应使用独立结构。密钥引用由服务端生成，不能让客户端指定文件路径；私有文件先以正确权限创建再写内容，不能先明文写入普通临时目录再修改权限。
- 保存新 Key 时先写新的私有文件，再一次性保存模型设置和新引用。保存失败清理本次新文件，原设置与原 Key 继续有效；不要先覆盖旧 `.env` 再保存地址。
- 已有环境变量／`.env` 方式继续兼容。用户明确填写新 Key 后使用新保存的 Key，不能被旧环境变量悄悄覆盖。
- 查询接口只返回 `key_configured`、配置来源和非敏感状态，不返回 Key；运行快照仍不含 Key 明文。旧密钥文件在没有可继续运行记录引用后才可清理。

来源明确区分 `stored`（私有文件）、`env`（原环境变量／`.env`）和 `none`（明确不使用密钥）。旧数据默认 `env`；填写新 Key 选择 `stored`；明确清除后选择 `none`，不能回退读出旧 `MODEL_KEY`。`key_configured` 按所选来源判断，不仅检查是否存在引用。清除取消当前配置对后续新任务的绑定，已有运行仍按原快照处理；页面说明这不等于在服务商处撤销 Key。

设置增加内部修订号，界面不显示版本选择。提交时在现有 `run_gate` 与数据库事务内核对读取时的修订号，再保存设置、来源和新引用；冲突返回 409，保留表单并要求重新读取，不能自动覆盖另一页面刚保存的配置。新密钥文件未被数据库引用、或提交结果不明时，清理先核对引用；启动恢复不删除仍被设置或可继续运行记录引用的文件。

### 测试反馈

区分保存失败、密钥无效、无权限、地址或接口不匹配、模型不存在、不支持图片、超时及返回格式错误。错误不回显请求头、Key 或服务商可能包含敏感信息的完整响应。

## 二、没有本地工具时自动使用模型读字

### 统一规则

| 情况 | 处理 |
| --- | --- |
| 本地工具可用 | 保留当前本地读字路径 |
| 未安装或工具不可用，模型可用 | 使用模型读取文字，再交给原判断规则 |
| 两者均未配置 | 开始任务前明确提示缺少可用读字方式，不先操作手机再失败 |
| 本地工具成功返回空文字 | 按“识别成功但无文字”处理，不因此重复调用模型 |
| 看不清、接口失败、响应不完整、次数用尽 | 保留失败原因，当前条件视为无法确认；不得自动走“不包含”或“已超时”分支 |

运行前能检查是否安装、是否填写 Key；网络、权限和图片能力以实际识别测试／请求结果为准。页面显示“本地可用”“将使用模型读字”“尚未配置可用读字方式”，不能只显示“本地文字识别：未安装”而让用户误认为所有识别都不可用。

### 自动替代的边界

替代只覆盖本地读字程序缺失、无法启动、超时、非零退出或结果格式损坏。截图失败、设备离线、手机身份不符、显示屏／标注尺寸不匹配、停止或人工接管，都按原原因处理，不调用模型掩盖问题。同次观察中的本地失败后最多切换一次，模型读取同一张已核验截图，不重新取另一张画面混用。

设置页不要把“已填写 Key”等同于“模型已可用”。分别显示本地工具是否安装、密钥是否已配置、样图是否已验证，以及运行实际使用的来源。本地路径可用时不强制填写 Key；仅当本地不可用且需要替代读字时，才要求有效的模型配置。

### 截图中的“奖励”条件

1. 核对手机编号、当前显示屏和框选区域。
2. 获取当前截图，先确定全部文字需求。仅有区域文字条件且没有页面依据时，可以合并需要的区域裁剪识别；存在 `guard` 页面依据时，读取完整截图。
3. 本地工具不可用则把图片交给模型，要求提取文字和位置，不允许模型生成点击或修改工作流。
4. 将结果转换为原有文字结构，坐标还原到原图。
5. 程序继续执行原有“是否包含奖励”的判断，保留原连线和后续步骤。

模型返回“看不清／无法确定”时停止本次条件判断；只有明确读字成功，才允许根据提取结果判断“包含”或“不包含”。组合条件、轮次和当前应用等非文字条件仍由原代码处理。

页面依据检查与区域内目标文字匹配保持分开。不得因为裁剪掉框外标题，导致原本有效的 `guard` 永远无法匹配；也不得把框外的“奖励”用于框内条件。所有局部坐标必须映射回原图，先验证手机、显示屏和原图尺寸，再应用标注。

### 文字结果约定

模型读字使用单独的 `TextReadResult`，包含必填的 `status`（`ok`／`uncertain`）、整体可信度和 `words`；每个词包含 `text`、原图坐标 `x/y` 与可信度。不得把缺失字段默认成空数组或成功状态。

- 检查文本类型、原图内坐标、有限的 0–1 可信度及数量上限；越界、低可信、无法确定或不完整响应统一按无法确认处理，不钳制坐标后继续。
- 模型读字接纳门槛使用 0.85，与独立模型检查一致；自报高可信不是正确性的证明，仍需真实正反截图验收。`ok` 空数组仅在响应完整且明确表示读字成功时才代表空文字；`uncertain`、解析失败或缺少 `words` 不能变成“不包含”。
- 文字读序、词块拆分和数字独立性必须通过原有 `Frame::text`、`region_text` 的固定样本检查；不能把“奖／励”随意拆成带空格的文字，导致文字匹配失效。
- 模型读字输出预算独立于现有判断接口的 512 token；初始上限 4096 token，保留现有 1 MiB 响应字节限制，最多 512 个词块、文字合计 16 KiB。超限、模型输出截断或结束状态表明未完成时，保留明确错误，不静默裁掉后继续判断；需要更多内容时提示缩小识别范围。
- 原视觉判断接口及本地 OCR 不套用新的模型文字响应格式；共用 HTTP 传输，但分别解析和验证各自的返回结构。

### 最小实现范围

- 在共享文字识别入口增加本地／模型适配，沿用 `Frame`、`Word` 和现有文字匹配规则，不复制一套工作流执行器。
- 为模型读字增加有明确状态的文字结果结构；独立模型看图检查仍保留自己的返回结构。共用模型 HTTP 请求与接口解析，避免两套配置、超时和错误处理。
- 为共享入口传递运行上下文和需要识别的区域，覆盖画布条件与等待条件。同步修改启动检查和所有直接调用 `recognition::frame` 的位置，不能只修设置页或截图中的单一分支。
- 同一次观察只取一张图，相同区域共用读字结果；不同手机、屏幕尺寸或动作后的观察不复用旧结果。多个区域需要合并识别时保留坐标映射及各条件的区域过滤。
- 模型调用计入已有 `model_calls` 和任务预算，取消、人工暂停、超时与迟到结果处理沿用现有机制。不得通过新适配器绕过调用上限；编辑器任务上限按下方预算设置保存。
- 每次模型读字记录来源、步骤、截图时间、耗时、调用次数和失败原因；模型配置与读字选择策略使用启动时的快照。修改设置影响新任务，不替换正在执行的任务配置。
- 重复文字判断与长时间等待同样受预算限制；开始前提示将使用模型及当前预算。模型替代不承诺与本地工具相同的速度和调用量。
- 独立模型看图检查继续保留。固定坐标点击、滑动等无需读字的任务，不额外要求模型配置、不增加模型调用。

### 时间、次数与恢复

- 一次观察最多发出两次模型请求，发送前就持久化尝试次数；只有临时连接故障、限流等可恢复问题允许在剩余时间内重试。鉴权失败、接口／模型不匹配和不支持图片不重复发送相同请求；本地失败后不会在本地与模型之间往返重试。
- 等待条件的截图、本地尝试、模型请求及重试都计入原等待时长。超时大于零时，发起每次观察前先检查剩余时间，单次请求上限为剩余等待时间与 60 秒中较小者。识别仍在进行时到达截止时间，则取消识别并按无法确认处理，不采纳迟到结果。
- 等待间隔自然到期时，如果最近一次有效观察明确“不符合”，且之后没有在途或失败的识别，进入原超时出口；没有有效观察则按无法确认处理。计时结束后不再补发一次注定超时的请求，避免正常“不符合”永远无法进入超时出口。
- 等待时长为零沿用原来的“立即观察一次”语义，使用单次识别上限；不符合才进超时出口，识别失败仍为无法确认。
- 普通条件沿用单次模型 60 秒上限。停止、人工接管或后台退出立即取消等待；迟到结果不得保存成成功判断或触发下一步。任务恢复只重复尚未完成的观察，不重放手机动作。
- 已有编辑器任务的运行记录缺少新字段时，保留启动时的模型快照与本地识别路径，不在恢复时自动绑定当前 Key 或新服务。无法按原配置继续时明确提示原因；重新启动工作流使用新的自动替代规则，不要求重做工作流。旧格式任务及其运行记录直接清理，不做恢复适配。

## 交付顺序与验收

| 单元 | 交付 | 验收标准 |
| --- | --- | --- |
| A. 模型设置 | 直接填写 Key、Base URL 兼容、保存状态、内置样图测试 | 填写后可保存，刷新和重启保留；Key 不回显；错误持续可见；同一 Key 能完成图片测试 |
| B. 自动读字替代 | 共享识别适配、原条件与等待条件继续使用、实际来源提示 | 无本地工具时通过下方覆盖矩阵；不改变原文字、页面依据、坐标、暂停恢复与调用预算语义 |

每个单元自测通过后提供预览，用户确认再部署并做本地最小提交。方案阶段不修改正式模型配置，不读取或测试用户尚未正确保存的真实 Key。

### 必做检查

- 配置：Key 含连字符可正常保存；空白保留、明确清除、保存失败回退、旧环境变量兼容、重启保留、接口不回显 Key。
- 地址：Base URL 带／不带尾斜线、完整接口、格式不匹配、旧数据兼容；保存不偷偷发模型请求。
- 接口：Responses、Chat Completions；401／403、404、模型不存在、不支持图片、超时、错误 JSON、输出截断和重定向拒绝。
- 读字：有／无本地工具、本地工具故障、两者均缺失、成功空文字、低可信与不确定结果；包含、不包含、组合条件与等待条件。
- 区域：框外同名文字不得影响框内判断；旋转、折叠屏、不同手机及尺寸不匹配时继续执行原有拒绝规则。
- 运行：模型次数与重试均计入预算；停止／接管期间不接受迟到结果；修改模型配置不改变已启动任务；不重放未确认点击。
- 回归：`cargo test`、模拟设备集成与识别隔离检查；网页类型检查、构建和浏览器日夜／窄屏验证；Mac／Linux 有本地工具的路径保持可用。

### 覆盖矩阵

| 场景 | 必须确认 |
| --- | --- |
| 页面文字、组合条件 | 区域内正反结果、框外同名文字、框外页面依据、词块拆分、成功空文字与无法确认 |
| 等待文字条件 | 立即满足、有效不符合后超时、零等待、模型慢于等待上限、限流重试与次数耗尽 |
| 固定坐标点击、直接滑动、纯按键 | 原本无需读字的路径没有额外截图、模型要求或调用；保持按手机标注与未确认动作保护 |
| 密钥与配置生命周期 | 同服务空白保留、跨服务显式沿用、明确清除不回退、两页并发保存、保存失败和重启引用恢复、旧测试结果失效 |
| 平台与工作流记录 | Mac／Linux 本地工具路径、Windows 无本地路径；编辑器任务的运行快照保留，不默换服务或重放动作 |

### 工作流调用次数

当前 `canvas::compile` 固定 `model_limit: 0`。接入模型替代时必须同步配置非零上限：在工作流编辑器提供调用上限，默认 10、允许 1～100 次；无文字需求不要求模型。上限写入已保存任务与运行快照，达到上限明确停止，不把无法读字当作否定条件。区域合并、重试和等待条件的每次实际请求均计数。
