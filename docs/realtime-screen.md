# 实时投屏

在“设备管理 → 查看设备详情 → 屏幕预览”点击“开启投屏”。手机需已连接、亮屏；需要密码时在手机上解锁。连接成功后显示“实时画面”和当前画面尺寸。

- 本阶段只看画面，可与自动任务同时使用；点按、拖动、键盘、声音和录像尚未接入。
- 同一台手机只允许一个工作台页面投屏；另一页面会提示先关闭原投屏。不同手机可以分别观看。
- 点击“停止投屏”、离开设备页、将页面切到后台、关闭网页或退出服务时，释放投屏连接。不自动重启投屏或任务。
- 画面按窗口高度适配；支持全屏的浏览器可点“全屏观看”，按 Esc 返回。
- 连接中可以取消；断线后清除画面并提示重新投屏，避免将旧画面误认作实时状态。
- 默认 H.264，最长边 1280 像素，最高 30 帧／秒，码率 4 Mbps；实际流畅度取决于手机、连接和浏览器。静止画面可能不持续产生新帧。
- 旋转后跟随视频更新尺寸。首版使用 Android 主显示屏（display 0）；折叠屏切换需另行真机验证。
- “原图截图”继续使用现有 ADB 截图，用于小字识别及位置标注。当前没有将网页视频画面接入后台识别或截图接口。

## 浏览器

需要支持 WebCodecs H.264 解码的现代浏览器，建议使用新版 Chrome／Edge。Mac 本机使用 `http://127.0.0.1:17841` 或 `http://localhost:17841`。局域网普通 HTTP 地址通常无法使用视频解码；其他设备访问需安全的 HTTPS 地址。

## 安装

在项目目录运行：

```sh
python3 scripts/setup-mirror.py
cargo build
cd web
npm ci
npm run build
cd ..
python3 scripts/install-service.py install
```

下载脚本从 scrcpy 官方发布获取固定的 3.1 服务端，验证 SHA-256 后保存至 `data/bin/`。安装脚本复制到正式服务目录。首次开启投屏会将服务端推送至已核验的手机临时目录，关闭后尝试删除本次文件；断线时手机端文件可能残留，可在下次连通后手动清理 `adb-studio-*.jar`。

## 连接与资源

Rust 后台沿用现有手机编号核验，固定本次 ADB transport；通过独立名称的 ADB reverse 通道接收视频，经已鉴权的同源 WebSocket 转发给 Svelte。通道与会话名称独立于 Aya，不会关闭其他软件的投屏。手机端 `control=false`、`audio=false`、`power_on=false`，只启动视频编码。

网页使用 `@yume-chan/scrcpy` 解析协议，使用 `@yume-chan/scrcpy-decoder-webcodecs` 解码并显示到画布。转发与解码队列有上限，处理过慢时结束连接并提示重开；不会无限积压画面。手机上的受保护内容可能显示黑屏。

## 检查与验收

```sh
cargo test
python3 scripts/check-mirror.py
python3 scripts/check-integration.py
cd web
npm run check
npm run build
```

模拟检查涵盖访问限制、手机核验、原样转发、重复会话、拒绝触控消息、重开、启动取消、息屏提示与服务退出清理；不操作真机。

用户验收：开启后观察手机正在变化的页面；检查画面连续性、延迟、旋转、停止后重开、切页停止、断线提示。分别核对 USB／无线、不同手机和常用浏览器。观看期间任务应保持原状态，任务不会因投屏结束而开始或继续。

下一功能单位：接入点按、拖动、返回与主页，并与人工接管共用手机操作限制，用户验收后单独提交。
