# 已保存任务的编辑与归档

状态：已部署到本地工作台，界面调整已由用户确认并要求本地提交。更新日期：2026-10-27。

## 现状与目标

“自动化任务”展示的是可运行版本。编排器另存草稿，已有再次打开、自动保存和删除草稿的能力。首次实现只给 `manual-<UUID>` 任务在“更多”里显示编辑，而正式工作台 8 项任务中只有 1 项属于此类，因此用户在其余卡片上看不到入口。删除草稿也不会移除可运行版本。现在每张已保存的任务卡片都要有直接可见、可用的“编辑”，归档与恢复也应适用于每项任务。

## 功能一：继续编辑

- 每张未归档的任务卡片直接显示“编辑”。有草稿的手工编排任务打开 `/editor?draft=<UUID>`，准确选择对应草稿，不依赖浏览器记住的上次草稿。
- 旧格式任务及草稿已删除的任务打开“编辑任务”页：从最新保存版本复制内容，通过名称、说明、适用手机、步骤名称与常用参数表单修改；复杂步骤提供按步骤的高级数据编辑，保留其余字段和判断样本。保存时只新增版本，不覆盖旧版。页面须明确新版本需试跑才能启用。
- 草稿可比当前启用版更新。界面保持“保存草稿”与“保存新版本”两个动作；编辑草稿不会改变正在运行的版本。新版本按既有检查、试跑、启用规则处理。
- 编辑器删除草稿时，若已有正式版本，确认文案须明确“任务仍保留；之后可在任务版本编辑页修改，但原画布布局无法恢复”。

## 功能二：归档与恢复

- 所有已保存任务均可归档。任务卡片“更多”提供“归档”；确认窗显示名称、运行与定时影响。运行中或暂停中的任务先停止，后台拒绝归档。
- 归档任务从默认列表移出。“已归档”筛选可查看并恢复。归档保留草稿、所有正式版本、启用版本指针和既有执行记录，不删除手机数据。
- 后台保存独立归档标记。归档时禁用该任务全部定时；恢复后定时仍保持禁用，由用户自行重新开启。归档期间，普通运行、试跑、启用版本、新建或启用定时均被后台拒绝，不能仅靠网页隐藏按钮。
- 服务端用定时锁与运行锁串行处理归档、定时触发和启动，防止归档后仍有新任务启动。重复归档或恢复返回当前状态，刷新网页后状态一致。
- 已归档任务在列表和详情显示明确状态；归档中不提供运行或试跑。恢复后沿用归档前已启用版本，无须重复试跑。

## 界面与接口

- 任务卡片底部直接显示“编辑”；省略号按钮提供带任务名称的无障碍标签，“更多”菜单容纳详情、记录与归档，已归档卡片直接提供恢复。菜单可用键盘操作，归档二次确认，成功后给出提示。列表布局见 [网页组件](ui-components.md#自动化任务列表)。
- `GET /api/workflows` 为每个版本提供 `archived` 状态；原有版本数据不改写。
- `PUT /api/workflows/{id}/archive` 归档；`DELETE /api/workflows/{id}/archive` 恢复。后端核对该任务确实存在。
- `GET /api/workflow-drafts` 用于判断任务是否仍有草稿。草稿和正式版本的关联仍由 `manual-<UUID>` 确定。

## 彻底移除

`DELETE /api/workflows/{id}` 用于用户明确要求的彻底移除。运行或暂停中的任务须先停止；后台按定时锁、运行锁的顺序检查，并用事务清除该任务的全部版本、启用指针、归档标记、模型验证记录、关联画布草稿和定时设置。历史执行记录保留，但已移除版本不能继续执行。内置任务只保留防止重新生成的编号标记，重启不会恢复任务内容。

## 验收单位

1. **编辑入口**：现有 8 项任务的卡片均直接显示“编辑”。画布任务进入对应草稿；定点点击、定时滑动及复杂旧任务进入已有版本的编辑页。修改后只新增版本，旧版仍可用；刷新后新版仍在，试跑前不自动启用。保存失败时页面内容仍在。
2. **归档与恢复**：包括旧格式任务。有运行中任务时拒绝归档；停止后归档，默认列表消失、归档列表可见；定时全部停用；普通运行、试跑、启用与定时接口拒绝归档任务；恢复后任务与记录仍在，旧定时不会自动恢复。重启后台再看状态不变。

每项先做自动检查和隔离模拟检查，再请用户在工作台试用。用户确认达标后，分别做本地 Git 最小单位提交。
