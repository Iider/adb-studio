# 纯视觉识别

支持 macOS 与 Linux。纯视觉任务不调用 Swift 或本地文字识别；原有任务默认保持本地优先。截图会发送到“系统设置”中保存的模型服务。

## 先检查一张图

“系统设置 → 识别检查”选择手机当前画面或本地 PNG，填写判断条件；需要定位时填写目标，需要读数时勾选读取整数。检查不会点击手机。

结果显示判断、依据、位置或数字、截图与模型耗时、请求次数。红圈只标记模型位置。无法确认、缺字段或越界都会显示具体结果，不会执行操作。先保存模型设置，再做识别检查。

- PNG 最大 8 MiB，宽高最多 8192 像素；上传按图片解析限制内存。
- 一次检查最多请求 2 次，每次最多等待 60 秒；同一后台同时只接受一个检查或截图样本验证。
- 返回 `unknown` 表示无法确认，不算正确识别或任务成功。
- 样本保存在后台 `data/vision-samples/`；检查记录保存在数据库，不包含密钥。样本用于工作流验证，暂不自动清理，备份时一并保留。

## 接口

`POST /api/recognition/check` 继续使用现有同源检查与令牌，不接受任意文件路径。两种图片来源只能选一种：

```json
{
  "device_id": "手机自身编号",
  "query": {
    "condition": "当前是系统设置首页，WLAN 入口可见",
    "target": "WLAN 入口中心",
    "region": [0.05, 0.1, 0.95, 0.6],
    "read_number": false
  }
}
```

使用本地图片时去掉 `device_id`，改传 `image_base64`（纯 PNG 的 Base64，不带 data 前缀）。返回的目标位置已由后台从模型约定的 0–999 坐标换算成原图像素。`region` 为宽高比例 `[左, 上, 右, 下]`，默认全屏。`target` 可省略；读取数字时将结果放在 `result.coin`，并非只支持金币。

返回包含 `id`、`image`、`captured_at`、`size`、`query`、`model`、`calls`、`capture_ms`、`model_ms`、`result` 和 `error`。模型识别失败仍返回检查记录，由 `error` 说明原因；请求参数错误返回 HTTP 400。

`GET /api/recognition/samples/{image}` 读取该检查保存的 PNG，需要相同访问凭据。`image` 是后台返回的 UUID 文件名。

## 制作一个纯视觉任务

参考 [WLAN 入口示例](../examples/vision-tap.json)。示例没有真实手机样本，不能直接试跑；先收集图片、收紧按钮区域并填写适用手机。系统设置包名也需从目标手机核对。

工作流增加 `"recognition":"vision"`。不填则保持 `local`。识别方式由工作流版本固定，网页显示本次方式和模型预算，不提供强制把旧任务改成纯视觉的开关。

新增两类步骤：

| 类型 | 字段 | 行为 |
| --- | --- | --- |
| `vision_check` | `package`、`condition`、`next` | 核对应用并确认页面；不确定则结束为“需要处理” |
| `vision_tap` | `package`、`guard`、`target`、`region`、`verify`、`next` | 确认页面与目标，用新图再次定位，点击前复查目标区域，再点击并用新图验证结果 |

`vision_tap` 的 `guard` 是操作前条件，`verify` 是操作后成功条件。允许区域应包围已采样的唯一按钮，避免包含其他可点击入口。两次定位相差超过 12 像素，或画面尺寸、目标区域发生明显变化时，不点击。区域相似不是成功依据，点击后仍需模型检查。

可组合等待、启动应用、原有直接动作与结束步骤；本地读字步骤和汽水高频任务不能混入纯视觉版本。直接动作仍按现有约定执行，不因纯视觉模式额外获得页面保护。

### 截图样本

先通过识别检查保存图片，再把返回的文件名填入工作流 `tests`：

```json
[
  {"node":"wlan","image":"正确页面的UUID.png","expected":"confirmed","target_region":[0.08,0.2,0.35,0.3]},
  {"node":"wlan","image":"干扰页面的UUID.png","expected":"unknown"},
  {"node":"wlan","image":"成功后的UUID.png","expected":"confirmed","after":true},
  {"node":"wlan","image":"失败后的UUID.png","expected":"unknown","after":true}
]
```

这里的文件名仅为说明，必须换成实际返回的 UUID 文件名。定位正样本必须给出人工确认的 `target_region`，不能只检查模型是否返回坐标。`vision_check` 至少需要一张正样本和一张干扰样本；`vision_tap` 还需操作后的成功、失败样本。每个版本最多 40 张样本。

提交版本后，调用现有 `POST /api/workflows/{id}@{version}/validate`。后台按该步骤的条件重新请求模型，每张样本请求一次，保存实际结果、预期结果、模型配置与耗时；任意样本失败都不能通过。样本检查不操作手机，费用另计，不扣某次运行的预算。

命令工具默认等待 150 秒；样本较多时可用 `python3 scripts/studio.py --timeout 600 request POST /workflows/编号@版本/validate` 延长等待。

试跑入口会重新验证样本，然后执行。样本调用量在“验证样本并试跑”按钮旁显示，运行预算另列。保留未用于调整提示词的截图作独立验收，不能只用同一组图片反复调到通过。

### 运行保护

- 沿用版本不可覆盖、样本验证、真机试跑通过后启用的规则。更换模型配置后，需要重新验证和试跑。
- 开始时固定模型名称、接口地址、接口类型与密钥变量名；不保存密钥内容。进行中的任务不随设置变化切换模型。
- 单次视觉点击至少预留 3 次请求，分别用于定位、复查和操作后验证；重试也计入预算。默认上限 10 次，工作流最高 100 次。
- 停止或人工接管会取消模型等待；迟到的结果不能继续操作。已发出但结果不明的点击不重放，需要停止任务并核对页面。
- 断线、锁屏、换应用、屏幕尺寸变化或结果不确定时，沿用现有等待或需要处理机制，不自动降低判断要求。
- 截图证据、模型结果和分段耗时与运行编号关联。检查记录保存至 `vision_checks`，样本验证保存至 `vision_validations`，运行判断保存至 `vision_results`；三者均通过后台存储，不能直接修改验证标记。

旧记录缺少模型快照时沿用原模型读取方式；新的纯视觉记录必须带快照。高频金币读取、连续刷视频的纯视觉版本仍需单独适配，不属于本轮迁移范围。

## 开发检查

```sh
cargo test --locked
cargo build --locked
python3 scripts/check-vision.py
python3 scripts/check-integration.py
python3 scripts/check-mirror.py
```

隔离检查使用模拟手机和模拟模型，覆盖两类模型接口、样本验证、点击前后检查、越界、未知结果、定位漂移、预算、暂停及 HTTPS 来源，不调用真实模型或操作真机。真实模型的准确性、等待时间与费用需按实际截图单独验收。

部署与发行见 [Mac／Linux 部署](deployment.md)。
