# 增加工作流副本导入

## 需求与决策

提供创建新工作流和导入文件入口。用户查看操作卡片后要求两项都放回右上角，因此保留原任务网格，在工具栏增加导入按钮，不增加操作卡片。

导入按既定方案先交付独立副本，不覆盖已有任务、不启动任务、不创建定时。复用当前文件结构、校验器、弹窗样式和编辑页；覆盖导入留待下一单元。

## 改动

- 新建与导入按钮位于任务页右上角；窄屏刷新按钮仅显示图标，保留无障碍名称。
- 导入弹窗预览内容、名称、图片和手机信息，允许修改名称；成功后提供编辑入口，纯草稿直接打开编辑器。
- 后台重新校验文件，重新生成外层任务、草稿与图片编号，保留内部引用、布局和本体与草稿差异。
- 工作流、草稿、操作摘要同一事务写入；重试复用同一操作编号。失败回退，启动清理中断残留并保留其他任务引用的图片。
- 使用 SHA-256 计算请求摘要；接口、使用说明与页面规范同步更新。

## 验证

后台 39 项测试、模拟设备集成检查、导出与副本导入隔离检查通过；网页类型检查、构建及原有 18 项测试通过。检查包含预览不写入、并发重试、图片重新编号、未完成草稿、错误输入、事务失败和重启清理。

浏览器验证导入成功、错误提示、改名后重试、返回焦点、深色及 390px 窄屏布局。使用模拟 ADB 和独立数据提供本机预览，等待用户验收后部署与提交。覆盖导入尚未实现。

## 验收与正式部署

用户确认验收通过并要求更新正式工作台。2026-10-28 完成 release 构建，备份原安装与数据后更新正式 Windows 后台。程序与网页校验一致，已有工作流、草稿、运行记录、定时及访问凭据保持不变，导入预览接口验证正常。新增与导入按钮位于右上角，覆盖导入仍待开发。
