# 补充 Windows 部署

## 需求

保留 macOS、Linux 使用方式，补充 Windows 支持，在当前电脑部署并使用。

## 方案与关键决策

- 共用原有后台和网页，平台差异集中在程序路径、权限、退出与安装脚本，避免复制业务逻辑。
- Windows 使用当前用户启动文件夹和 `pythonw.exe` 隐藏运行，无需管理员权限；未采用系统服务，减少安装依赖。文件锁阻止重复启动，本地停止请求让后台完成退出处理。
- Mac 保留 launchd，Linux 保留 systemd；Windows 与 Linux 一样不附带本地文字识别引擎，支持纯视觉和不依赖读字的任务。
- 官方 Windows ADB 与两个配套 DLL 一起安装、打包；ZIP 排除数据库、截图和密钥。

## 改动

- `src/platform.rs`、`src/main.rs`、`src/adb.rs`、`src/recognition.rs`：Windows 程序路径、用户权限、隐藏子进程、正常退出、Python 识别程序支持。
- `scripts/install-service.py`、`windows_service.py`、`setup-adb.py`、`package-release.py`：安装、登录自启、启停、官方下载和 Windows ZIP。
- `scripts/check*.py`、`fake-adb.py`：Windows 模拟程序调用、正常停止、并发日志和文件关闭；发行包检查支持 ZIP。
- `.github/workflows/release.yml`：加入 Windows x86_64，保留 Mac／Linux 构建。
- 部署说明、README、识别说明与工作台配对提示同步更新。

## 验证

- 当前 Windows x86_64：后台 32 项测试、网页 4 项测试、类型检查与构建通过。
- 模拟设备、编排器、纯视觉、投屏、平台配置与发行包检查通过，包含配对协议失败的中文提示。
- 当前用户安装、停止、重新安装、保留数据、启动快捷方式、重复启动保护通过。
- 中文和空格数据路径、源码自动查找 ADB、独立 ZIP 解压启动通过。
- Windows 网页显示本地服务连接、平台 `windows · x86_64`、自启已安装；截图保存在不提交的 `data/verification/windows-settings.png`。
- WSL Ubuntu 的平台配置检查通过；未在 Mac 实机或 Linux 上完整运行后台测试。云端构建尚未触发。
