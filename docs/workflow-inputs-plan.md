# 工作流运行变量开发方案

状态：运行变量、弹窗与紧凑列表、变量取消单位均已通过用户验收并部署至 Windows 本地正式工作台。日期：2026-10-29。

在“开始”节点定义多个变量；其他节点选择引用；每次运行可临时填写，也可全部使用默认值。临时填写不修改工作流，暂停、断线及后台重启后继续使用本次运行的值。

## 使用示例

| 在开始节点创建 | 默认值 | 使用位置 | 本次运行填写 |
| --- | --- | --- | --- |
| 循环执行轮次 | 5 | 循环 → 重复轮数 | 10 |
| 滑动等待时间 | 2 | 滑动 → 两次之间的间隔（秒） | 3 |
| 滑动结束后等待 | 0 | 滑动 → 结束后等待（秒） | 留空，使用 0 |

保存一次工作流后，后续只需选择手机、填写本次参数、点击运行。一个变量可供多个节点引用，所有引用使用同一个值。

“两次之间的间隔”和“结束后等待”继续分开：滑动仅执行一次时，没有两次之间的等待；完成全部滑动后，再执行一次结束后等待。

## 首版范围

支持**整数、数字（可带小数）**两类变量，覆盖轮数、次数和时间。每个变量都有默认值，因此首版没有必须临时填写的项目。

| 可引用的节点 | 字段 | 现有执行限制 |
| --- | --- | --- |
| 循环 | 重复轮数 `count`、轮间间隔 `interval` | 轮数 1～10000 的整数；间隔 0～86400 秒 |
| 点击、滑动 | 重复次数 `count`、两次之间的间隔 `interval`、结束后等待 `after_wait` | 次数 1～10000 的整数；等待 0～86400 秒 |
| 滑动 | 滑动时长 `duration_ms` | 100～2000 毫秒 |
| 等待 | 等待时长 `seconds` | 0～86400 秒 |
| 等待条件 | 最长等待 `timeout`、检查间隔 `interval` | 大于 0，最多 86400 秒 |

首版不增加公式、运行中赋值、节点输出变量、文字插值或独立变量节点。文字条件、应用编号、坐标和循环轮次判断值暂保留现有填写方式；后续按实际需求扩展类型与引用字段。

## 页面交互

### 开始节点：变量列表

- 点击“开始”，右侧显示紧凑变量列表，每行仅有别名（未填时为名称）、默认值、编辑与删除图标；标题旁“＋”添加变量。开始节点保持唯一、不可删除。
- 添加和编辑使用弹窗，保存后一次写入变量定义并自动保存草稿；取消、关闭或 Esc 不修改原值。弹窗复用共用下拉框、遮罩与滚动条，窄屏中内容滚动，底部操作保持可见。
- 每项填写名称、类型、默认值；可选显示别名、说明、最小值和最大值。显示别名最多 40 字，留空使用名称；别名不改变变量编号或引用。
- 名称支持中文，去除首尾空格后需唯一，长度 1～40 字；说明最多 200 字；每个工作流最多 20 个变量。
- 默认值必须是有限数字，整数类型不接受小数。范围可留空；填写时最小值不得大于最大值，默认值必须在范围内。
- 变量只保存整数或数字，不设置单位。次数只接受整数变量；时间字段可引用整数或数字变量。单位由节点字段决定，同一个变量在不同字段中按各字段含义解释，不自动换算。
- 支持调整顺序、重命名和删除。范围、说明及显示顺序放在弹窗“更多设置”。重命名保留引用；已被引用的变量禁止直接删除，删除图标的悬停说明列出引用节点，解除引用后再删除。
- 弹窗保存前检查名称、默认值与范围；保存工作流时检查类型与已有引用，不暗中改变其他节点的值。
- 只添加变量也算有内容的草稿，需要自动保存；单纯打开空白工作流仍不自动生成后台草稿。

### 其他节点：选择引用

- 支持的数值字段提供“固定值／使用变量”切换，默认保持固定值。
- “使用变量”下拉框只按字段所需的数值类型筛选变量，显示别名及名称，未填别名时显示名称；没有可用变量时提示“请先在开始节点添加变量”。
- 同一变量引用多处时，有效范围为变量范围与各字段范围的交集。不存在合法交集时禁止保存；默认值必须满足全部引用。
- 字段显示“使用：滑动等待时间 · 默认 2 秒”，不要求用户输入变量编号或特殊语法。
- 切回固定值时填入该变量的默认值，再由用户调整。
- 画布摘要显示变量名称；动作总数预估在编辑时按默认值计算并标注“按默认值估算”，运行面板按本次填写重新计算。
- 下拉框、表单错误、键盘操作和滚动区域复用[前端规范](../.agents/skills/adb-studio-frontend/SKILL.md)，变量较多时面板可滚动，运行按钮保持可见。

### 运行：临时填写

- 编辑器运行面板、设备页“直接运行”和任务详情共用“本次运行参数”表单；没有变量的工作流保持现有界面。
- 每项优先显示别名，未填则显示名称；默认值直接回显在紧凑输入框中，宽屏并排、窄屏换行。变量表单和变量记录不显示单位，也不显示外框、默认值提示、范围说明和恢复默认按钮。
- 空白表示使用默认值；数字 `0` 是实际输入，不能当作未填写。
- 每次新的运行从默认值开始，不自动沿用上次临时填写。启动失败保留已填内容；切换工作流后清除旧输入；设备页和任务详情切换执行手机时也清空临时值。
- 类型、范围及引用错误在字段旁显示；校验失败不创建运行，不发手机命令。
- 未保存的工作流仍沿用“先保存再运行”。保存完成后，以保存结果核对变量定义，再提交临时值；定义变化导致输入失效时保留面板并提示修正。
- 运行中只读展示本次参数。暂停再继续不重新询问、不重新取默认值；“重新运行”视为一次新运行。
- 执行记录保留变量名称、默认值、本次生效值及是否临时填写，便于解释实际执行结果。

## 数据与执行设计

### 定义、引用与本次值

草稿和工作流顶层增加 `inputs`，省略视为 `[]`。数组顺序就是运行表单顺序。每个变量使用自动生成的 UUID，用户只操作中文名称。

以下为局部数据示意，编号以短名代指实际 UUID：

```json
{
  "inputs": [
    {"id": "rounds-id", "name": "循环执行轮次", "type": "integer", "default": 5, "min": 1, "max": 10000},
    {"id": "wait-id", "name": "滑动等待时间", "type": "number", "default": 2}
  ]
}
```

节点字段允许原有数字或严格的引用对象，例如循环 `config.count = {"input":"rounds-id"}`、滑动 `config.interval = {"input":"wait-id"}`。只解析上表允许的字段；不对整份 JSON 做文字替换，也不执行表达式。

变量编号只需在所属工作流内唯一。复制或导入整个工作流时保留内部编号和引用；重命名变量不改编号。删除后新建同名变量得到新编号，不自动接管旧引用。

### 校验与保存

使用 `src/workflow_inputs.rs` 模块，集中负责定义检查、引用检查、范围交集和解析，避免各节点各写一套替换规则。

1. 草稿保存沿用可保存未完成内容的规则，允许暂时缺默认值或有失效引用，但限制结构、数量和体积。页面展示待修复项。
2. 保存为可运行工作流时，检查全部定义、引用和默认值；用默认值生成临时执行副本，再运行现有完整校验。
3. 数据库中的工作流仍保存变量定义及引用，不能将默认值解析结果覆盖回本体。
4. 可选样本检查也对默认值解析后的副本进行；导出时比较本体与草稿应保留变量差异，不因两份定义碰巧解析成相同数字就认定一致。

### 启动接口

复用 `POST /api/runs`，新增可选 `inputs`：

```json
{
  "device_id": "3430131496001EB",
  "workflow_id": "manual-草稿UUID",
  "inputs": {"rounds-id": 10, "wait-id": 3}
}
```

- 省略 `inputs`、传 `{}` 或省略某个变量，均使用对应默认值。
- 网页空白输入不发送该键。接口只接受数字，不把 `null`、空字符串、数字字符串或布尔值自动转换成数字；未知变量编号返回 400。
- 开始运行时在现有任务锁内读取当前已保存工作流，合并默认值与本次输入，检查全部引用，再生成执行副本。手动与定时走同一条解析路径。
- 错误包含变量名称、节点名称和字段，例如“滑动等待时间：等待条件的检查间隔必须大于 0 秒”。运行前校验全部节点，不能执行到一半才发现另一分支参数无效。
- `Run.workflow` 保存已替换为具体数字的执行副本；增加 `Run.inputs` 保存本次生效值、`Run.input_overrides` 保存临时输入。工作流内 `inputs` 定义保留名称、别名和当时默认值，不包含单位。
- 上述新增运行字段读取旧记录时默认为空。执行、暂停恢复和重启恢复只读取运行记录，不重新解析最新工作流。
- 继续复用手机身份核对、同机互斥、动作恢复检查及计时；不修改循环、间隔和结束后等待的执行含义。
- 命令工具增加 `run --inputs-file <JSON文件>`，传同一份编号到数字的映射；原有 `run` 命令仍走默认值。

### 定时与文件兼容

- 首版定时不单独保存临时值，界面注明“使用工作流默认值”。每次触发读取当时已保存的默认值；手动运行填写不会影响定时。已启动任务不受之后修改影响。
- 新程序继续读取旧草稿、工作流和运行记录，缺少 `inputs` 就按无变量处理；现有固定数值无需迁移。
- 旧变量的 `unit` 字段兼容读取并忽略，保存与导出不再携带；数值不换算，编号和引用保留。旧浏览器恢复副本也只丢弃该字段，避免误报内容不同。
- 有变量的可运行工作流使用 `schema_version: 2`；无变量保留 1。校验器接受两版，但第 1 版禁止变量定义和引用。旧程序会明确拒绝第 2 版，避免忽略变量后错误执行。
- 导出文件中任一本体或草稿含变量定义／引用时使用 `format_revision: 2`；其余继续导出 1，空 `inputs` 省略。新导入器支持两版，检查版本与内容一致性，拒绝未知版本。
- 导出带走定义、默认值、引用与排列顺序；临时运行值属于执行记录，不进入工作流文件。本体和未完成草稿的变量配置分别保留。
- 副本导入维持现有新建工作流编号、内部引用保留、手机标注保留的行为，不自动运行或建立定时。
- 部署前备份数据；开始使用变量后，不直接用旧程序读取新数据，回退需恢复对应备份。

### 必须覆盖的检查

- **值与边界**：多变量、同变量多处引用、只覆盖一项、全部默认、有效 `0`、小数、整数错误、上下限、未知编号、失效引用、无合法范围交集。
- **执行结果**：循环轮数、点击／滑动次数、间隔和结束后等待都按实际值执行；一次滑动无两次之间的等待；确定路径核对准确动作数；含分支或提前退出的流程，实际次数不超过面板上限。
- **保存隔离**：临时值不改变草稿、本体及默认值；仅有变量的草稿能保存；真正空白草稿不产生新的“未命名工作流”。
- **恢复隔离**：暂停、断线及后台重启后本次值不变；另一次运行使用不同值互不影响；运行启动后更改本体默认值不影响已有运行。
- **入口一致**：网页、命令工具和定时共用校验；输入非法时未创建运行、未发送动作；原有同机互斥仍生效。
- **文件往返**：有变量和无变量文件、草稿与本体不同默认值、仅草稿、旧版导入、未知版本、损坏引用；不得悄悄丢弃变量。
- **页面体验**：变量较多、窄屏、日夜主题、键盘选择、错误定位、启动失败保留输入、切换工作流清空临时值。

后端执行改动运行 `cargo test`、`python3 scripts/check-integration.py`；扩展 `scripts/check-editor.py` 与 `scripts/check-workflow-export.py` 覆盖保存和文件场景。前端运行 `npm run check`、`npm run build`。执行测试使用隔离模拟设备；用户真机验收选择已准备好的页面与目标手机。
