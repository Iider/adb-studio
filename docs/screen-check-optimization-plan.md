# 动作前屏幕检查优化方案

状态：已实现并部署 Windows 本地服务 17841，必要检查通过，用户验收通过。

## 依据与目标

2026-10-30 15:54:30，V2171A 在第 18 次滑动前执行 `exec-out screencap -p`，12.013 秒未返回，任务暂停。详见[超时证据](adb-timeout-diagnosis.md)。优化前只为检查屏幕尺寸，也会生成和传输完整 PNG；实测一张约 1.76 MB，曾耗时约 3.84 秒。

目标：减少尺寸检查的手机 PNG 压缩与整图传输开销；保留真实尺寸、显示屏、折叠形态和手机自身编号核验。截图、模型识别及编辑器标注仍取完整图片。

## 实施方案

1. `src/adb.rs::size` 优先通过已核验的连接读取原始截图头部。手机端执行 `screencap | head -c 12`，多屏时向 `screencap` 指定已识别的物理屏幕编号；命令仍统一经 `src/adb.rs` 执行。
2. 头部只含宽、高、像素格式，核对长度、合理尺寸和支持的格式；不缓存上次尺寸，不用固定分辨率或 `wm size` 替代实际截图尺寸。
3. `canvas_screen` 保留动作前后的显示信息核对，以及现有显示屏与触控编号映射；读到尺寸后继续匹配原标注。旋转、折叠切换、断线或标注不匹配时不得发送动作。
4. 头部缺失、格式不支持或手机不支持截取头部时，记录回退原因并使用现有完整截图路径；ADB 超时或权限拒绝直接沿原错误处理，不再追加完整截图重试。
5. 保留 12 秒命令时限、超时日志、任务进度和未确认动作保护。不修改随机参数、动作次数、等待、模型规则、投屏画面及网页亮度。

该方式仍会在手机端抓取一次画面，但跳过 PNG 压缩与整图回传。若卡在手机抓取本身或其他命令，仍可能超时，需由新日志区分。

## 选择原因

- 使用截图头部：尺寸来自同一截图机制，减少厂商显示信息格式差异造成的误读。
- 不仅靠显示信息解析或 `wm size`：物理尺寸、旋转后的实际尺寸、覆盖分辨率与折叠屏可能不同；本轮不另建厂商解析规则。
- 不缓存尺寸或取消检查：避免旋转、折叠和换屏后按旧坐标操作。
- 不直接延长超时或自动重试动作：避免掩盖卡点及重复手机动作。

## 检查与验收

- Rust：正常头部、横竖屏、不同像素格式、截断／异常／过大尺寸。
- 模拟设备：正常点击与滑动不取完整 PNG 检查尺寸；PNG 路径不可用仍能完成轻量检查；不兼容回退正常；头部超时保留进度且不追加 PNG；换屏、旋转、断线与错误手机编号阻止动作。
- 运行完整模拟集成检查和节点编辑检查，确认原截图与标注、单步测试、暂停恢复及其他流程保持可用。
- 构建后备份并更新本地后台；不覆盖网页、草稿、工作流和凭据。更新前核对任务状态，保留暂停进度；有运行中任务时先完成准备，再安排安全更新。
- 用户实机：沿用原工作流、连接与投屏设置连续运行，观察是否仍超时；如再次发生，按日志判断是头部检查、完整截图回退还是其他命令。
