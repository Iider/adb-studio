# 已保存任务的编辑与删除

已通过隔离检查与用户验收，2026-10-28 部署至本地正式服务。

## 继续编辑

- 每项任务直接提供“编辑”。有画布草稿时打开 `/editor?draft=<UUID>`，其余任务打开 `/workflow-edit?id=<任务编号>`。
- 草稿自动保存未完成的编辑；手动“保存”校验后覆盖当前本体。每项任务只有一份本体，不生成历史版本或快照。
- 修改只影响之后的运行，已启动任务使用启动时的内容。
- 只在编辑器中删除草稿时，已经保存的任务仍保留，可通过普通任务表单继续编辑；原画布布局不会恢复。

## 删除任务

任务卡片“更多 → 删除任务”打开确认框。确认框显示具体名称，以及将删除的内容：

| 内容 | 处理 |
| --- | --- |
| 工作流本体、关联画布草稿 | 删除 |
| 关联定时设置 | 删除 |
| 全部执行记录 | 删除，包括此前已从列表清理的记录 |
| 执行事件、模型判断与样本验证结果 | 删除本任务关联记录 |
| 运行截图目录 | 删除本任务全部执行记录对应目录 |

删除不可恢复；取消或 Esc 不改变内容。运行、等待手机、恢复中、暂停或仍在收尾的任务，必须先停止并等待结束。手机本身的数据不受影响；其他任务的内容、记录与截图保留。

归档、恢复和归档筛选已移除。旧数据升级时仅清除任务归档标记，任务重新显示；原先已停用的定时仍保持停用，不自动执行。

## 接口与保存一致性

- `GET /api/workflows` 只返回当前任务，不再附带 `archived` 状态。
- `DELETE /api/workflows/{id}` 删除任务及上表关联内容。后台按 `schedule_gate → run_gate` 检查，避免定时触发、继续执行或正在结束的任务写回记录。
- 数据记录在同一个数据库事务中删除。失败时整体回退；运行记录清除后不能再续跑、导出或读取原事件。
- 同一事务写入待清理的运行编号，随后删除对应截图目录；文件清理完成后移除清单。截图暂时无法删除时返回 `cleanup_pending: true`，网页明确说明，后台约每 30 秒和启动时重试；不把未清完的截图报告为全部完成。
- 内置任务仅保留防止重新生成的编号标记，后台重启不会恢复任务或历史内容。
- 普通任务编辑器保存时带 `If-Match: *`；任务已经删除则返回 412，保留页面编辑，不重新创建任务。草稿旧校对编号也不能重建已删除的草稿。
- 原 `/api/workflows/{id}/archive` 路径不再提供服务，返回 404。

运行截图与任务记录属于删除范围。独立识别检查生成的公共样本不属于某次任务执行记录，保留以供其他任务使用。

## 验收

1. 菜单只显示删除入口，没有归档、恢复或归档筛选；确认框明确名称、范围与不可恢复，取消和 Esc 返回原按钮。
2. 运行、等待、恢复、暂停时拒绝删除；停止后删除成功，旧页面不能保存复活，旧记录无法继续。
3. 任务、草稿、定时、当前和已清理的历史记录、判断结果及截图一并消失；其他任务和独立识别检查保留。
4. 模拟数据库失败时全部回退；模拟截图目录删除失败时保留待清理编号，后台重试或重启后完成。
5. 旧归档任务升级后可见，定时保持原停用状态；删除内置任务后重启不会重建。

以上检查使用隔离端口、临时数据与模拟设备完成；正式部署后核对原任务、草稿与执行记录保留，未在正式数据上执行删除测试。
